# Internationalisation

- Locales: `id` (default) and `en` — `packages/i18n/src/index.ts`.
- `apps/web`: next-intl with `localePrefix: 'as-needed'` → Indonesian has no prefix (`/desa/baros`), English uses `/en/desa/baros`.
  The URL determines the language. Browser preferences and locale cookies are ignored.
  Call `setRequestLocale(locale)` in every layout/page so pages stay static.
- Visitors change the display language from `/pengaturan` or `/en/pengaturan`. The switch links to the canonical
  settings URL for the chosen language. Internal links keep the active locale.
- Messages: shared in `packages/i18n/messages/{id,en}.json` (namespace `common`), app-specific in
  `apps/<app>/messages/{id,en}.json`. Both locales must have the same keys.
- `apps/dashboard`: Indonesian only for the MVP, but all copy goes through next-intl (`src/i18n.ts`) so EN can be added.
- URL segments are Indonesian for all locales (ADR 0008: `/jelajah`, `/desa/[village]`, `/produk/[product]`, `/tentang`; route folders use Indonesian names, params and code stay English). Old English URLs redirect (308) via `next.config.ts`; content slugs stay in Indonesian.
- User content (products, businesses) is written in Indonesian; English comes from `*_translations` when present,
  falling back to Indonesian. Machine translation is a phase-2 feature.
- Prices are always IDR (`formatRupiah`), formatted with the UI locale.
- SEO: every page sets `alternates` with `pageAlternates(path, locale)` (`apps/web/src/lib/site-url.ts`): its own
  canonical URL plus `id`, `en` and `x-default` (the unprefixed Indonesian page). `<html lang>` follows the locale.
  Search engines can follow links on the settings page, which uses `noindex`.
  `sitemap.xml` (`apps/web/src/app/sitemap.ts`) lists indexable public pages per locale with the same alternates, from
  `GET /v1/sitemap` (slugs and `updatedAt` of public villages, businesses and products, same visibility rules as the
  public endpoints, cached an hour at the CDN). It renders per request so an API failure is an error, never an empty
  sitemap. `robots.txt` allows crawling only on a production site (`VERCEL_ENV=production`, or a non-localhost
  `NEXT_PUBLIC_WEB_URL` off Vercel); previews and the dashboard answer "disallow everything".
